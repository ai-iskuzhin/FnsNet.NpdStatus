# FnsNet.NpdStatus Working Agreement

Правила проекта для сопровождающих и для ИИ-агентов.

## Назначение

`FnsNet.NpdStatus` — .NET SDK для одного публичного сервиса ФНС: проверки статуса плательщика НПД
по ИНН и дате.

SDK даёт типизированный клиент, модели запроса и ответа, типы ошибок и регистрацию в контейнере. В
нём не место бизнес-правилам приложения, хранению в базе, коду эндпоинтов ASP.NET Core и рабочим
процессам.

## Чего SDK не делает — и почему это решение, а не упущение

Ни повторов, ни ограничения частоты, ни кэша, ни проверки ИНН. Сервис разрешает два запроса в
минуту на IP-адрес; как распорядиться этим бюджетом — свойство продукта, а не протокола. Добавить
это в библиотеку значит навязать политику всем, кто её возьмёт.

`AddNpdStatusClient` возвращает `IHttpClientBuilder` именно поэтому: обработчики добавляет тот, кто
знает своё приложение.

## Разметка репозитория

```text
src/FnsNet.NpdStatus
tests/FnsNet.NpdStatus.Tests
docs/api.md
```

Один пакет. Другие сервисы ФНС — в своих репозиториях, со своими версиями.

## Тесты

**Все тесты работают без сети, и это обязательное требование.** Сервис не резолвится из-за пределов
России: тест, который пошёл бы в сеть, падал бы у большинства и проходил бы у меньшинства — это
хуже, чем отсутствие теста.

Тела ответов в тестах — из официального описания и из живых замеров, записанных в `docs/api.md`.

## Контракт

Описание прямо требует игнорировать незнакомые поля в ответах: сервис может их добавлять без
поднятия версии API. Десериализация обязана это выдерживать, и на это есть тест.

Коды ошибок — открытое множество. Незнакомый код должен доходить до вызывающего как есть, а не
схлопываться в «неизвестная ошибка».

## Версии

Semantic Versioning. Порядок выпуска — в [`docs/release.md`](docs/release.md). При смене версии
правятся все пять полей в `.csproj`: иначе `dotnet pack` молча соберёт пакет со старым номером.
